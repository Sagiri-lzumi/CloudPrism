# 加密链路自测指南（WindowsGo）

> 目的：让用户用**一份本地密库 + 自己的一批文件**，把「加密 → 存储 → 解密」
> 整条链路跑通并核对每个环节的产物形态。全部步骤在普通 PowerShell 里双击
> exe 操作（IDE 沙箱内 Chromium 起不了窗口，见 manual_smoke.md 前置说明）。
> 建议新建一个测试目录（如 `D:\cp-test\`）与测试文件，避免误动真实数据。

## 0. 预备知识：日志位置

- 一切异常的排查入口：**exe 同级的 `data\logs\`**（滚动日志，恒 3 个文件、
  每个 2MB，中文文案、不落任何明文密钥）。
- 遇到「与下文预期不符」时，把该目录一起拷出发我分析，并附：当时在哪个
  页面点的什么按钮、界面提示的原文。

## 1. 新建密库并拿到恢复码

1. 启动应用 → 密库页 → 「初始化向导」→ 模式选**新建密库**。
2. 后端类型选**本地文件夹**，选刚才准备的测试目录。
3. 库名随意；**文件名加密打开**（这一步要验证文件名形态）；设主密码
   （两次一致，建议测试用弱密码即可，但请记住）。
4. 完成后预期：
   - 弹**保存恢复码**对话框（全局模态，不随页面切换消失）；
   - 点「复制恢复码」粘贴到记事本另存为 `recovery.txt`（离线保存语义）；
   - 关闭对话框进入文件页；
   - **失败观察点**：若对话框没出现、或关闭后想再找恢复码——恢复码只展示
     这一次（库内密文存有，但界面不重放），只能靠「重新生成恢复码」。

## 2. 上传文件并核对远端密文形态

1. 文件页点「上传」，选 2–3 个不同型文件（一张 jpg、一个 txt、一个 5MB+
   的大文件，比如安装包或视频）。
2. 传输页观察进度/速度正常；结束后任务可清空。
3. 打开资源管理器到测试目录，预期：
   - 出现 `xxx.cpenc`（原名 + 密文后缀），或者乱码名 + `.cpenc`；
   - 文件**打不开**：双击会提示损坏/未知格式（内容已被加密，且头尾有
     认证段，不是简单改名）；
   - txt 用记事本打开是乱码（无法读出任何原文语义）；
   - 目录里还有密库自身的元数据/索引容器文件（固定名，同样不可读）。
   - **失败观察点**：若远端出现能直接打开的明文原文件 → 加密没生效，
     立刻停用该库并反馈。

## 3. 下载 / 预览解密正确

1. 预览：点选图片立即显示原图；txt 显示原文内容（与本地原件一致）；
   视频可播放且能拖动进度条。
2. 下载：把 jpg 下载到另一个目录，与原件大小一致、可正常打开；
   用 PowerShell 比对哈希应一致：

   ```powershell
   Get-FileHash D:\cp-test\原图.jpg -Algorithm SHA256
   Get-FileHash D:\cp-test-下载\原图.jpg -Algorithm SHA256
   ```

3. 导出（右键 → 解密导出）到新目录同样可打开。
   - **失败观察点**：任何一步解密出错（乱码、损坏、卡进度）→ 带日志反馈。

## 4. 文件名加密的远端结构不可读

1. 若第 1 步开了文件名加密：上传一个含子目录的本地文件夹。
2. 资源管理器里核对：文件与目录名均为加密形态（无明文、不可猜测含义），
   路径长度也被压缩（对照 ARCHITECTURE 差异：不保留原始树层级）。
3. 界面内（Go 端文件页）看到的仍是**明文目录树与文件名**——密文名只在
   后端存储可见。
   - **失败观察点**：资源管理器里能看到明文文件名/目录名 → 文件名加密
     未生效，反馈。

## 5. 锁库 → 重连 → 恢复码开库

1. 点导航轨的锁库钮（或 Ctrl+L）→ 回到密库页并提示「密库已锁定」。
2. 最近记录卡片快速重连：只输主密码 → 成功进入文件页，浏览态正常。
3. 断开（锁库）后走**忘记密码**路径：连接表单开「忘记密码/恢复码」，
   粘贴 `recovery.txt` 里的码（允许小写与空格分隔）→ 应能开库成功。
   - **失败观察点**：恢复码开库失败 → 可能是码抄错（注意 O/0、I/1），
     再核对一次；仍失败则带日志反馈。
4. 追加验证：用恢复码开库成功后，故意输错一次密码连接 → 应提示密码错误，
   **状态栏回「未连接」、无悬挂文案**（本轮修复点，顺带回归）。

## 6. 断点续传

1. 下载一个大文件（≥100MB）到一半时，任务管理器强杀 exe。
2. 重启应用 → 连库 → 底部状态栏出现「N 个任务可续传」提示（或传输页
   横幅），点它 → 任务从接近断点处继续（看速度与已下载字节），完成后
   文件哈希与原件一致。
   - **失败观察点**：从头重传、或完成后文件损坏 → 带日志反馈。

## 7. 可选：跨端互操作（Py ↔ Go）

1. 用 WindowsPy 版连接同一个测试目录（同一库），能列出并解密 Go 版上传
   的文件；反向同理（Py 上传 → Go 下载）。
2. 预期：两端互相读写一致（协议层已互通测试全绿，此为运行态复核）。
   - **失败观察点**：一端开库报「格式不识别/版本不支持」→ 带两端日志反馈。
